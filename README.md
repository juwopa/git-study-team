### 2.팀 채팅 릴레이로 기본 기능 익히기
박주원 : Commit 메시지는 제가 작업한 내용을 적었고 Push를 하니까 파일이 업로드되면서 History에 기록되었습니다. 다른 사람의 History에선 Commit에서 추가된 부분이 초록색으로 표시되었고, 삭제된 부분이 붉은색으로 표시되었습니다.
김동현 : "2번째, 5번째로 Pull을 진행하였고, Pull을 하지 않은 경우 로컬 저장소의 파일이 업데이트되지 않았습니다. Commit 메시지는 신경을 쓰지 못했습니다... Push시 원격 저장소에 제가 추가한 커밋이 올라갔으며, History탭에서는 다른 분들이 작업한 커밋 내용들이 표시되었습니다."
임현규 : Pull은 3번째와 6번째에 진행했고, 커밋 메시지는 신경 쓰지 못했습니다. 충돌은 일어나지 않은 것 같습니다."
최성규 : Commit Push Fetch Pull 의 기본 기능을 이해하고 하였습니다.


### 3.브랜치 파서 서로 피드백 남기기
박주원 : 브랜치 이름은 "feedback-주원"이라고 지었습니다.
feedback-주원을 먼저 merge했고, 그 다음은 feedback-성규 -> feedback-현규 -> feedback-동현 순서로 총 4번의 merge를 했습니다.
서로 브랜치에 review.md파일을 만들고 여기에 각자 피드백을 적었습니다. 이 파일을 merge하는 과정에서 2가지 문제가 생겼습니다. 첫번째는 review.md에서 충돌이 일어났습니다. 이때 충돌 문제를 알려주는 기호 텍스트가 추가되었습니다. 그래서 이 문제는 vsc를 열어서 충돌이 일어난 부분의 기호 텍스트를 지우고 줄 바꿈해주는 것으로 충돌을 해결했습니다. 두번째는 review.md.txt로 파일 이름을 다르게 생성한 팀원이 있어서 파일이 review.md에 자동으로 합쳐지지 않았습니다. 그래서 이 문제는 review.md.txt의 텍스트를 review.md에 붙여넣는 것으로 문제를 해결했습니다.
김동현 : "브랜치 이름은 'feedback-동현'으로 생성했습니다. Merge는 총 3번 진행하였으며, 주원 -> 성규 -> 현규 -> 동현 브랜치 순서로 머지를 진행했습니다. 성규님 머지부터 충돌이 발생하였으며, 1~3번째 줄에 각 자 작성한 내용에서 충돌이 발생했습니다. 충돌은 notepad로 파일을 열어 내용을 수정 후 해결했습니다.
최성규 : "feedback-성규의 review.md 와 review.md.txt 문제 윈도우11 탐색기 보기 표시 파일확장명"
임현규 : 브랜치 이름은 Feedback-현규라고 지었고, 머지는 순서대로 진행하다가 중간에 제 파일이 사라져서 확인해 보니 파일명이 달라서 수정 후 다시 진행했습니다.


### 4.stash 해보기
박주원 : boss.cs파일을 작업하다가 팀원의 요청으로 팀원의 브랜치를 봐줘야하는 상황에서 boss.cs를 stash해야하는 상황이였습니다. stash를 사용하니까 작업하던 boss.cs파일이 github desktop에서 changed files에 표시되지않았고, 다른 팀원의 브랜치를 봐주고 다시 돌아와서 Restore했을때 작업하던 boss.cs이 그대로 유지됐습니다.
김동현 : 팀원 A가 main 브랜치에서 보스 밸런스를 조정을 하는 도중, 팀장이 긴급 수정용 hotfix/shop-crash 브랜치로 즉시 이동해 달라고 요청하는 상황입니다. Stash 전에는 작업한 파일들이 남아있으나 이후에는 임시 저장공간에 작업한 파일들이 저장되었습니다. Restore 후에 원래도 이전에 작업한 파일들이 돌아오게 되었습니다.
임현규 : 상황은 주원님이 보스파일을 수정하던 중간에 stash하였고 , stash 전에는 변경된 파일들이 Changes 탭에 표시되고 커밋하지 않은 수정 내용이 그대로 보이는 상태였습니다. stash 후에는 Changes 탭이 비어 있는 것처럼 보였습니다. GitHub Desktop에서는 "Stashed Changes"라는 항목으로 따로 관리되고 있었습니다. Restore 했을 때 원래 작업하던 코드가 그대로 돌아왔습니다.
최성규 : Restore 했을 때 원래 작업이 그대로 돌아와서 신기했습니다. 


### 5.삽질한 거 하나는 팀원별로 꼭 쓰기
박주원 : 브랜치를 merge하는 과정에서 어떤 부분에서 충돌이 일어났고 이 부분을 확인하고 수정하는 작업이 헷갈렸습니다. 
김동현 : "3번 브랜치 파서 서로 피드백 남기기" 과제에서 병합을 시도했음에도 review.md파일에 다른 팀원이 작성한 내용이 추가되지 않았습니다. GitDesktop에서는 병합이 정상적으로 완료되었다고 떴기에 의아해 했으나 원인을 확인해보니 "review.md" 파일과 "review.md.txt" 두 가지 파일이 존재하였고 이를 하나로 통합하여 해결했습니다..
최성규:
1. 깃 허브 로그인 후 이메일 초대 수락 하기
2. review.md 파일 확장자 확인하기
3. 작업 전 Fetch 해주기
4. 커밋 메시지 생각 해보기
임현규 :
문제: 머지 과정에서 파일이 사라진 것처럼 보여서 문제를 확인함.
원인: 실제로는 파일명이 달라서 Git이 다른 파일로 인식한 것.
해결: 파일명을 수정한 뒤 다시 커밋하고 머지 진행, 정상적으로 복구됨.


### 6.마무리 정리
# Git 기초 요약
| 주제 | 핵심 명령어 | 한 줄 설명 |
|---|---|---|
| 저장소 만들기 | `git init` / `git clone <url>` | 새로 시작하거나 기존 저장소 복제 |
| Commit | `git add .` → `git commit -m "메시지"` | 변경사항을 기록으로 저장 |
| Push / Pull | `git push` / `git pull` | 원격 저장소와 주고받기 |
| Branch | `git checkout -b <이름>` | 새 작업 공간 분리해서 작업 |
| Merge | `git merge <브랜치명>` | 다른 브랜치 내용을 합치기 |
| 충돌 해결 | 충돌 표시(`<<<`~`>>>`) 직접 수정 → `git add` → `git commit` | 같은 부분을 여러 명이 고쳤을 때 정리 |
| Stash | `git stash` → `git stash pop` | 커밋 전 변경사항 잠깐 보관/복원 |

**흐름**: 저장소 생성 → 수정 → commit → push/pull → (branch로 나눠 작업 → merge) → 충돌 있으면 수정 → 급할 때 stash
